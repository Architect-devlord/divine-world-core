The critical CPU spike is deliberation — at horizon=12, n_trials=40, that's 480 WorldModel forward passes per deliberation event. On a modern CPU core with a ~10M parameter Transformer, that's roughly 1–2 seconds per deliberation. Deliberation fires every ~5–10 cognitive cycles, so roughly every 5–10 seconds per agent. 20 agents staggered = near-constant load across cores.
Per god agent (excl. oracle which is on Pi):

Same architecture + GodAbilityHead + heavier deliberation parameters. Estimate ~1.4GB RAM, ~1.5× CPU load of a normal agent. Assuming 4 god types: ~5.5GB RAM.
Minecraft Paper server (25 agent-players + plugin):

The Java plugin routes HTTP/WebSocket to 25 agent ports per tick. ~10–12GB Java heap, 4 dedicated cores minimum.
ScyllaDB:

25 agents writing memory events continuously. Needs NVMe storage — ScyllaDB's latency degrades badly on spinning disk. ~8GB RAM, 4 cores, NVMe mandatory.

On GPU — Why Not Now
The current architecture runs one process per agent with no shared GPU state. If you add a GPU today, all 25 processes will fight over CUDA context switches, which is often slower than CPU for small Transformers at this batch size (1 sample per agent per step). The GPU becomes valuable when you have a model serving layer — one process that owns the GPU and queues inference requests from agents. That's future architectural work (not in the current plan).
When GPU becomes worth it: once the model serving layer exists, a single RTX 4090 (24GB VRAM) could serve all 25 agents' WorldModel inference in batches of 25, reducing deliberation time from ~1.5s to ~50ms per agent. At that point it's transformative. For now it's premature.

Pi Oracle Connection
Nothing to worry about here. The oracle's observation payload is tiny: 128 floats × 4 bytes = 512 bytes per request. Even at 10 deliberation requests per second, that's 5KB/s. Standard LAN with <5ms RTT is all you need. Keep the Pi on the same local network and it's a non-issue. The only thing worth checking is that your router doesn't introduce jitter — give the Pi a static IP so the agent's HTTP client doesn't hit DNS on every call.
